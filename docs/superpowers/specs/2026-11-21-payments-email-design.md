# Paystack payments and Resend transactional email

User authorises payment/email integration and branded templates across purchases, invoices, enquiries, replies and payment notifications. Preserve existing React/Vite/Express/SQLite structure and sage/olive editorial design. Keys remain server-only environment variables. No credentials are present; complete locally with provider fakes and fail honestly when configuration is missing. Live activation additionally needs account keys, verified sending domain, notification inbox, public HTTPS origin and provider webhook configuration.

## Payments
Create an order using server-calculated ZAR cents and stock reservations, then initialise hosted Paystack checkout server-side. Persist a private payment-access token and deterministic transaction reference; retries reuse the order and reference. Never accept browser totals or callbacks as proof of payment. A return page verifies with the server; signed raw-body webhooks independently settle payment. Verify reference, amount, currency, customer and integration mode. Support modern timestamped Paystack-Signature and legacy x-paystack-signature with no downgrade when the modern secret is configured. Repeated/out-of-order notifications cannot duplicate settlement or emails. Cancelled-order late payments are recorded with an owner action warning, without reopening/refulfilling the order. No automatic refund or money movement from an admin status selector.

## Email lifecycle
Durable SQLite outbox inserts in the same transaction as order/enquiry/payment changes; email failure must not roll back an accepted purchase or enquiry. Resend delivery uses unique persisted event keys and Idempotency-Key, bounded timeout, retry/backoff, and a restart-safe worker. Preserve the exact payload during provider retries. Track sent/delivered/delayed/bounced/complained/failed statuses through signed Resend webhooks and prevent status regression. Add owner delivery log/retry controls and readiness status, never expose credentials or email bodies publicly. Enquiry replies are explicit owner sends, persist with the conversation and use the branded template. No automatic replies based on private notes.

Events/templates: order-received, invoice, payment-received, payment-failed, payment-pending, order-confirmed, order-fulfilled, order-cancelled, refund-received, refund-failed, enquiry-received, enquiry-reply, owner-order, owner-payment, owner-enquiry and owner-alert. Templates use table-based email-safe HTML and text alternatives, escaped dynamic content, itemised ZAR totals, delivery and invoice references, readable mobile layout, restrained botanical branding and a real configured Reply-To. No web fonts, scripts, forms, trackers or invented business/tax details. No card information in database or emails. Verified refund events notify customers; cancellation never implies a completed refund.

## Public and owner experiences
Checkout shows provider readiness, redirects only to allowlisted HTTPS Paystack checkout, handles pending/failed/cancelled returns and preserves a safe recovery token across reload. Clear the bag only on verified successful payment or intentional request-only submission when Paystack is unconfigured. Owner inbox supports composing and viewing replies; orders identify provider-managed payments and prevent manual overrides. Notification page shows configuration, delivery attempts, retries and actual template previews. Include private printable invoice access using the payment token or owner session.

## Verification
Meaningful tests cover signed/forged/replayed webhooks, body integrity, mode/amount/currency mismatch, callback tampering, duplicate callbacks, failed initialisation recovery, secret isolation, outbox retries/provider ambiguity, enquiry reply access control, email escaping, template lifecycle and invoice arithmetic. Browser-check checkout returns, owner reply/log controls, template rendering and mobile/tablet/desktop layouts. Document exact environment variables, webhook URLs, event subscriptions and test/live activation steps using current official Paystack/Resend documentation.
